# 18 · S3 实施记录：核心圈逻辑接入

> 本文记录 S3（需求 A 的逻辑部分）的实施结果、**为验证而查实的语法**、
> 以及**尚待确认的遗留项**。S2 的空壳窗口与美术见 `docs/16`。

## 1. 本轮做了什么

把 S2 的"空壳窗口"接上真实数据：席位能随国策填充、窗口能显示角色立绘与名字。

| 文件 | 内容 |
| --- | --- |
| `common/scripted_effects/hof_ic_scripted_effects.txt` | 每角色一个入席效果（7 个） |
| `common/scripted_triggers/hof_ic_scripted_triggers.txt` | 空席/满席/已入席 触发器（9 个） |
| `common/scripted_localisation/hof_ic_scripted_loc.txt` | 席位名与头衔动态文本（14 个 `defined_text`） |
| `interface/hof_ic_portraits.gfx` | 14 个立绘 sprite（7 席位 + 7 候选栏） |
| `common/focus_inlay_windows/hof_ic_inlay_window.txt` | 重写：`scripted_images` 按席位变量选图 |
| `interface/hof_ic_scripted_gui.gui` | 席位框改为由 `scripted_images` 供给；名字/头衔改 `context_aware_text` |
| `localisation/simp_chinese/hof_ic_roster_l_simp_chinese.yml` | 7 个角色名 + 7 个头衔键 |
| `common/national_focus/soviet.txt` | 注入 7 个入口国策（同步脚本自动完成） |

### 数据模型

```
hof_ic_slot_1 .. hof_ic_slot_7 = 角色序号
                                    0 / 未赋值 = 空席
                                    1..7       = 具体角色
```

一套变量同时驱动三处：席位立绘、席位框空/满、名字与头衔文本。

## 3. 为验证而查实的语法（**不要凭记忆改**）

这几条都是本轮实际去读了原版或 R56 文件才敢用的：

| 结论 | 依据 |
| --- | --- |
| `scripted_effects` / `scripted_triggers` 文件**没有包装层**，效果直接顶层 `名称 = { }` | 原版 `common/scripted_effects/GER_scripted_effects.txt`、`00_scripted_triggers.txt` 示例注释 |
| `scripted_localisation` 用 `defined_text = { name = X  text = { trigger = {…} localization_key = Y } }` | 原版 `common/scripted_localisation/00_scripted_localisation.txt` |
| **无 `trigger` 的 `text` 块是合法兜底写法**（恒真） | 官方文件里找到 54 处同款样例 |
| 席位变量**不需要初始化**：`check_variable` 对未赋值变量按 0 处理 | 原版德国的 `GER_ascended_advisor_N` 全库没有任何赋 0 的地方，而机制正常工作 |
| `compare = not_equals` 是「该值不等于」的惯用写法 | 原版 `germany.txt` |
| `context_aware_text` 是真实属性 | 官方 5 个 `.gui` 在用；**其中就有 `GER_inner_circle_scripted_gui.gui`（8 处）** |
| `GFX_focus_generic_soviet_politics` 真实存在 | 原版 `interface/goals.gfx` L158 |

### 原版德国到底怎么做的（我们的写法和它的差别）

原版**没有**参数化的脚本效果。它的「填第一个空位」是**内联在每个国策的
`completion_reward` 里**的一长串 `if / else_if / else`，且每个席位序号是硬编码的。

我们不能内联（7 个国策 × 7 层链太长），改成**每角色一个脚本效果**，链内同样硬编码
自己的序号 —— 与内联等价，但国策那边只剩一行 `hof_ic_seat_<key> = yes`。
**没有使用任何传参语法**（未经查证，不用）。

## 4. 立绘的自动降级

`build/gen-hof-ic-s3.ps1` 会先看 `docs/17` 约定的新美术是否已到位：

- **已到位** → 直接用 `gfx/interface/hof_ic/portraits/hof_portrait_SOV_*.dds`

所以美术交付后**重跑生成器就会自动切换**，`.gui` 一行都不用改。
这也正是 S2 建立的「sprite 间接层」要解决的问题（见 `docs/05` §5.7.2）。

> 尺寸说明：席位框是 131×139（长宽比 0.94），小图是 65×67（0.97），
> 比例接近，所以退回小图时**不会明显变形**，只是清晰度低。

## 7. 本轮踩到的坑（已修，记下来防复发）

1. **PowerShell 单引号不解释转义**：`` '`t' `` 是字面量「反引号 + t」，不是制表符。
   生成器里有大量 `'`t...'` 缩进写法，导致 `.gfx` 与 inlay window 里混进字面量 `` `t ``。
   → 在 `Write-ModFile` 里统一还原，并加「无 `` `t `` 残留」哨兵自检。
   **括号配平检查抓不到这个错**，所以必须单独设哨兵。

2. **`[ordered]@{1=…}` 的整数下标是位置下标**：`$od[1]` 拿到的是第 2 个值，
   整张映射表静默错位一格。
   → 改用普通数组 `@(...)` + `$roster[$idx-1]`，并在生成器末尾回读自检
     「`slot_1 = 1` 是否真的映射到第 1 人」。

3. **自检探针本身会写错**：两次假报错都出在探针正则——
   `\s*` 贪婪吃掉换行导致匹配失败；漏算 `trigger = { … }` 外面还有一层 `}`。
   → 判「失败」前先确认探针本身对。

4. **校验器只在自己 mod 里找贴图** → 引用原版/R56 素材时误报 14 项失败。
   → `texturefile` 按「本体 + 全部已加载 mod」解析，改为三处都查，
     找到外部素材时标注「【引用原版素材】」。

5. **终端会在命令开头注入杂散控制字符（`^U`）**：使第一条语句被当成命令名而失败，
   后续循环拿到空集合，产出**假的「未找到」结论**。
   → 别让命令以 `$var = …` 开头；改用脚本文件 + 任务方式运行。

6. **搜索盲区：漏掉 `dlc\<DLC名>\` 子目录** —— 这是本轮最值得记的一条。

   我连续几轮只搜 `<原版>\gfx` 与 `<原版>\interface`，于是得出结论
   「布哈林、李可夫没有大幅立绘，只有 65×67 小图」，并按此做了降级。
   实际上：

   - 注册表在 `dlc\dlc034_no_step_back\interface\nsb_portraits.gfx`
   - 贴图在 `dlc\dlc034_no_step_back\gfx\leaders\SOV\portrait_SOV_*.dds`（156×210）

   用户凭常识就指出这个结论不合理（「布哈林可以成为国家领导人」），
   而事实确实是错的——**14 个 DLC 里有 13 个带 `gfx\leaders`，根本不是个例**。

   → 生成器与校验器的素材查找根现在都包含全部 `dlc\*\`；
     并在生成器里加了「实测 DDS 尺寸，非 156×210 就显式告警」，
     让这类静默降级自己冒出来，而不是靠人眼发现。

   **教训**：结论与常识冲突时，先怀疑自己的检索范围，而不是先相信结论。
   以及：凡是要下「X 不存在」这种否定结论，先把搜索范围列出来自检一遍。

7. **`Get-Content` 没带 `-Encoding UTF8`，把中文注释写成了乱码**。

   `sync-from-r56.ps1` 用 `Get-Content -LiteralPath $p` 读 `build/inject-sov-seats.txt`，
   而 PowerShell 5.1 的默认编码是 **ANSI（本机 GBK）**，该文件却是 UTF-8 无 BOM。
   结果注进 `soviet.txt` 的注释变成「`鏍稿績鍦堝叆鍙ｃ`」这类乱码。

   为什么难发现：乱码全在 `#` 注释里，**不影响解析、游戏不报错**；
   而且注入的是 ASCII 的代码行，`error.log` 干净得很。
   → 修：加 `-Encoding UTF8`；
   → 防：新增校验 **9f**，把注入内容与源文件**逐字比对**。

   注意：同一脚本其余读文件处用的是 `[System.IO.File]::ReadAllText()`，
   那个默认就是 UTF-8，没问题。只有 `Get-Content` 有这个坑。

8. **国策缺本地化键，牌子上直接显示 id 原文**。

   截图里 7 个国策写的是 `hof_ic_seat_lev_trotsky` 而不是中文名。
   HOI4 用「`<focus_id>`」查国策名、「`<focus_id>_desc`」查说明，
   我只写了席位窗口要的 `hof_ic_name_*` / `hof_ic_trait_*`，漏了国策自己那两组。
   同样：**游戏不报错，只是显示原始 id**。
   → 修：本地化里补上 7 组名字 + 7 组说明（由生成器跟着花名册一起产出）；
   → 防：新增校验 **9e**，逐个国策检查这两组键是否存在。

   **共性**：这两条和前面几条都是同一类——
   **「HOI4 不报错，只是默默地难看/不生效」**。
   这正是不应依赖 `error.log` 作为唯一验收标准的原因。

9. **`context_aware_text` 少了方括号，界面上直接把键名印出来了**。

   截图里席位牌子上写的是 `hof_ic_seat_1_name`、`hof_ic_slot_1_trait` 这种原始键名。

   原版 HOI4 的 GUI 里两种写法**含义不同**：

   ```text
   context_aware_text = "Some_loc_key"       ← 引号   = 普通本地化键
   context_aware_text = [SomeDefinedText]    ← 方括号 = 脚本本地化 defined_text
   ```

   我们的 `hof_ic_slot_N_name` 是 `defined_text`（`common/scripted_localisation`），
   所以必须用**方括号**。我最初写成了裸的（既不引号也不方括号），
   引擎把它当字面量，于是原样印出来。

   依据：原版 `GER_inner_circle_scripted_gui.gui` 里两种都有实例 ——
   `context_aware_text = "GER_fuhrer_name_text"` 与
   `context_aware_text = [GetAscendedAdvisorTraitName1]`。

   → 修：`patch-hof-ic-gui.ps1` 改成**幂等**（未接线/方括号写错/已正确 三种状态都能处理）；
   → 防：校验新增 **9b-2**，专门检查有没有"裸的 context_aware_text"。

   **顺带一个正则教训**：这条哨兵第一版写成 `=\s*[^\["\r\n]`，
   结果每行都误报 —— 因为 `\s*` 会回溯成零个空格，
   让 `=` 后面那个**空格**被否定字符类匹配上。
   否定类里必须显式排除空白：`=\s*(?![\["\s])`。

10. **领袖位的头衔压在第一排席位上（真·布局错误）**。

    领袖容器 `y = 48`、高 165，占 48..213；但容器内部的头衔文本框在
    容器内 `y = 163`、高 20，实际伸到绝对 **y = 231**，
    而第一排席位从 `y = 224` 开始 —— **重叠 7px**。

    → 修：两排席位整体下移 8px（第一排 232、第二排 376、候选栏 523），
      保证 232..371 / 376..515 / 523..581 全部落在窗口 583 之内且互不重叠。

    **教训**：子组件超出父容器时，HOI4 不会裁剪也不会报错
    （容器普遍写着 `clipping = no`），所以"容器高度够"不等于"内容不越界"，
    必须把每个子项的 y + 高度都算一遍。

11. **同一个窗口里混用了两种锚点（orientation），导致底板与文字错位。**

    这是排版反复不对的**真正根因**。`.gui` 里当时是这么混的：

    | 元素 | 锚点 | y 的含义 |
    | --- | --- | --- |
    | 席位框 / 立绘 / 领袖圆框 | `upper_left` | 从容器**顶部**算 |
    | 席位/领袖的**文字** | `center_up` | 从容器**顶部**算 |
    | 席位/领袖的**名牌与底板** | `center` + `centerposition` | 从容器**中心**算 |

    而我是按"从顶部算"的直觉填的数，于是：

    - 席位容器高 139、中心 69.5 → 名牌 `y = 76` 实际落在 **145.5**（比文字低 56px）
    - 特质框 `y = 100` 实际落在 **169.5**（比文字低 70px）
    - 领袖容器高 165、中心 82.5 → 绸带 `y = 130` 实际落在 **212.5**，
      直接砸进第一排席位（截图里那块压在第一排上的红条）

    → **结构上的修法**：不再手改这个文件，改为 `build/gen-hof-ic-gui.ps1`
      **生成**整个 `.gui`，并强制：

      1. **所有元素的 `orientation` 一律用 `upper_left`**，
         y 永远从容器顶部算；水平居中由 `(容器宽 - 素材宽) / 2` 显式算出，
         不再用 `centerposition`。
      2. 生成器自带**布局自检**：竖向各段互不重叠（标题/领袖/两排/候选栏）、
         内容不越出窗口高度、锚点白名单检查。

    **教训**：HOI4 的 `orientation` 决定的是"y 从哪个参考点算"，
    不同 `orientation` 下同一个 y 值含义完全不同。
    一个文件里混用锚点，必然会在某个方向上错位 ——
    而且因为 `clipping = no`，它既不裁切也不报错，只靠肉眼发现。

    > 附带结论：`build/patch-hof-ic-gui.ps1` 已**被生成器取代**，
    > 不需要再运行（它仍然幂等可用，会报"全部通过"）。

12. **函数名撞上 PowerShell 内置别名，脚本被卡在交互提示上。**

    生成器里我把缩放函数命名为 `Sc`，而 **`sc` 是 `Set-Content` 的内置别名**。
    PowerShell 的命令解析优先级是 **别名 > 函数 > cmdlet > 外部程序**，
    所以 `Sc $SEAT_W_RAW` 根本没调到我的函数，而是去执行 `Set-Content`，
    又因为没给 `-Value`，弹出：

    ```text
    位于命令管道位置 1 的 cmdlet Set-Content
    请为以下参数提供值:
    Value[0]:
    ```

    脚本就停在这儿等输入。更坑的是：**后续命令会被当成它的 Value 吃进去**，
    于是终端看起来在“吞命令”，很难看出真正原因。

    → 改名 `Sc` → `Scale`；
    → 另外用 `Get-Alias -Name w,sc,center,scale` 查过，
      本机只有 `sc` 是别名，`w` / `center` / `scale` 都安全。

    **教训**：在 PowerShell 里给函数起名（尤其短名）前，
    先 `Get-Alias <名字>` 查一下。内置别名里短名很多：
    `sc` `si` `sl` `sp` `sv` `sls` `sort` `select` `type` `kill` `write` `group` `compare` 等。

## 12. 2026-09-16 第六轮：岔路二选一事件（修一个静默的真 bug）+ 人民委员介绍重写

### 12.1 起因：用户指出「有限市场化和劳动军不也得出一个事件来选」

查下去发现**不只是表现问题，是个真 bug**：

- 托洛茨基的 IV1`hof_ic_trotsky_limited_market_reforms`（有限市场化）与

  必然去点那条**已被互斥锁死的**
- 官方 `documentation/effects_documentation.md` 对 `complete_national_focus` 只写
  「completes a focus for a country」，**没有**声明它尊重 `mutually_exclusive`

所以没有卡死；但它同样「没有事件」，且 A 线会被驱动器绕过互斥继续强推。

### 12.2 做法：与终局**同一套标记驱动机制**（照德国 `GER_inner_circle_himmler.00`）

| 字段 | 含义 |
| --- | --- |
| `EvId` | 岔路事件 id（托洛茨基 1060 / 布哈林 1061） |
| `Char` | 打标记的角色 id |
| `Amount` / `Gates` | 触发门控（照终局用 `count_triggers`）；`Amount = 0` → 入席即可选 |
| `At` | 插在哪一条国策**之前**（必须是 `$Branch` 里的 id） |
| `Opts[]` | 两个选项：`Focus` / `Name` / `Flag` / `Opt` |
| `Term` | 「选了就自断这条线」的标记（兜底重排要停手） |

否则 `complete_national_focus` 会**绕过互斥**继续强推，树上留下
「A1 是空的、A2 却已完成」的断链。

**四处改动**（都在 §6 的驱动器里）：

1. `.1110`（开下一条）：在 `At` 那一条之前插入
   - **岔路未定** → 弹事件 + 重排自己（**绝不往前推**）
   - **岔路已选** → 只点亮被选中的那一条
2. `.1111`（完成）：同样在 `At` 之前插入「完成被选中的那一条」
3. 兜底 `else`：`limit` 里追加「**不是自断路线的标记**」——
   否则选了左翼共产主义后，剩下的国策永远完不成，兜底会每 3~6 天无限空转
4. 事件本体 + 本地化键（结构照抄终局那段）

⚠️ **链里不能出现空的 `else_if`** —— 「原地等待」那条必须带实际效果
（`country_event` 弹事件 + 重排自己）。

### 23.4 ⭐ 主干与形状

- **根 = 「车床边的书」** —— 20 岁成了彼得堡最好的车工之一；**工资的大部分花在自学和买书上**

追加时，`newline=None` 会把 `\n` 再翻成 `os.linesep`（`\r\n`），于是内容里原有的 `\r\n` 变成 `\r\r\n`。
🚩 **`bareLF = raw.count(b'\n') - raw.count(b'\r\n')` 这个检查【抓不到】`\r\r\n`**

→ **必须同时查 `raw.count(b'\r\r\n') == 0`**。
📌 **写长文档的稳妥做法**：写完后 `body.replace(b'\r', b'')` 再 `b'\r\n'.join(body.split(b'\n'))` 归一。
📌 **本轮已把这两篇修回纯 CRLF**（`docs/62` 409 行 / `docs/63` 324 行，`CRCRLF` 与 `bareLF` 均为 0）。
