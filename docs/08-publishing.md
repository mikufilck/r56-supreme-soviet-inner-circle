# 08 · 发布、依赖与兼容性

## 8.1 发布到 Steam 创意工坊

流程（⚠️ 启动器版本更迭会改 UI，步骤名以实际界面为准）：

1. Paradox 启动器 → **我的模组 / Mods** 标签页。
2. 找到你的 mod → **上传 / 发布**（首次发布会创建工坊条目）。
3. 填写标题、描述、缩略图（`thumbnail.png`，见 `descriptor.mod` 的 `picture` 字段）。
4. 首次上传成功后，启动器会把 `remote_file_id="..."` 写入你的 `.mod` 文件。
5. **更新** = 直接再次上传同一个 mod，覆盖工坊上的同一份内容。

其它渠道：

- **Paradox Mods**：启动器支持的可选平台。
- **手动分发**：打包 zip 给玩家，解压到 `mod/` 目录。

## 8.2 发布前检查

- [ ] `descriptor.mod` 与 `<mod>.mod` 的 `name` 完全一致（依赖与工坊识别都靠它）
- [ ] `supported_version` 正确
- [ ] `tags` 填写合理
- [ ] 工坊缩略图比例正常
- [ ] 描述里写明**依赖的 DLC**（若有）
- [ ] 清掉调试用代码（一键给资源、测试事件）
- [ ] 玩家人均会读的说明：加载顺序要求、是否需要新开档

## 8.3 依赖（📗 已更正语义）

```
dependencies={
	"Another Mod Name"
}
```

- 名字必须与对方**用户级 `.mod` 文件里的 `name`** 完全一致。建议**直接复制**，不要照启动器界面手打——wiki 特别提醒这类名字里可能混有难辨字符（例如 `–` en dash 被误打成 `-`）。
- 语义：**只改变加载顺序**，强制本 mod 排在 A 之后加载。它**不代表"必须安装 A 才能运行"**。子 mod 必须写，否则覆盖关系不成立。
- ⚠️ 典型故障 `Mod fails to load / 看起来什么都没改`：名字对不上，或与另一个 mod **重名**（两个同名 mod 同时启用时，只有先加载的那个文件生效）。
- 另一个常见坑：**自己订阅自己的工坊 mod**。会导致启动器里出现两个同名 mod，还会因为两处都有 `remote_file_id` 而破坏更新。没有理由订阅自己的 mod。

## 8.4 兼容性设计心法

| 做法 | 评价 |
| --- | --- |
| 新增自定义文件名 | ✅ 最安全，不破坏任何原版内容 |
| 覆盖原版文件（复制整份再改） | ⚠️ 必需时这么做；会与改同一文件的其它 mod 冲突 |
| `replace_path="目录"` | 🚩 谨慎。会让其它 mod 对该目录的所有改动失效 |
| 只改数值不新增文件 | ⚠️ 仍需整文件覆盖，注意后续原版更新会丢东西 |
| 用 `replace_path="history/states"` 做小改动 | 🚩 绝对不要——会导致丢失全部原版州 |

**冲突的本质**：两个 mod 改同一个文件的同一个位置 → 后加载者完全胜出，前者丢失。所以：
- 想最大兼容 → 尽量"新增"而不是"覆盖"。
- 必须覆盖时，在描述里写明"与 XX 类 mod 不兼容"。

## 8.5 DLC 依赖

- 引用 DLC 内容（如特殊科研、任务系统、势力平衡）时，玩家没装该 DLC 会出错或该内容消失。
- 建议做法：在关键 effect/trigger 里用条件判断 DLC（⚠️ 具体 trigger 名称需查原版），或干脆声明"需要 XX DLC"。

## 8.6 校验和与联机（📗 已补充机制细节）

- 主菜单版本号旁显示的 4 位 **checksum** 决定两件事：**能否联机**（必须与主机相同）、**能否拿成就**（必须与本体相同）。
- 哪些文件影响校验和，由游戏目录的 **`checksum_manifest.txt`** 决定。它涵盖：整个 `common/`、`events/`、`history/`，以及 `map/` 的大部分（**不含 `map/terrain/`**）。
- 推论：**只改动清单之外内容（例如纯本地化）的 mod 不会改变校验和**；改到清单内文件则一定改变。
- `-checksum` 启动参数会让 `system.log` 输出校验和比对明细——联机双方校验和不一致时，用它定位具体差异文件。

## 8.6b 存档隔离：`user_dir`（📗 wiki）

```
user_dir = "MyModSaveFolder"
```

- 改变存档存放的子目录。
- 效果是**双向隔离**：本体的存档不能在启用该 mod 时读取，本 mod 的存档也不能回到本体/其它 `user_dir` 不同的 mod 中读取。
- 用途：模组大幅改变游戏规则、不希望存档被跨环境加载时使用。

## 8.7 版本更新维护

游戏更新后：

1. 看官方变更日志（Changelog）；官方 DLC 发布的免费补丁也会改原版文件。
2. 把你覆盖过的原版文件**与新版对比**，把官方的改动合并进你的副本。
3. 更新 `supported_version`。
4. 在空存档（新档）上完整跑一遍：`error.log` 无新错误 + 关键功能可见可用。
5. 发布更新，并在工坊说明里注明"是否兼容旧存档"。

## 8.8 存档兼容

- **加内容**（新事件、新国策、新州）通常兼容旧档。
- **删内容 / 改 id / 改地图**通常会让旧档报错甚至崩。
- 结论：发布前务必在**新开的存档**上测试；若可能破坏存档，在说明里显著标明。
