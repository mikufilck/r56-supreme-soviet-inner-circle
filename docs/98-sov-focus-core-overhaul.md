## 4. 十二处国策效果改造（宣称 → 核心 / 追加核心）

### 4.1 🚩 实现机制（为什么这么做）

这些国策**不在我们自己的文件里** —— `soviet.txt` / `australia_taog.txt` 每次
由 `build/sync-from-r56.ps1` 从 R56 重新生成，**手工改会被下次同步覆盖**。所以全部走脚本的补丁表：

| 表 | 用途 | 本轮用到 |
| --- | --- | --- |
| `$FocusPatchMap` | 在 `completion_reward = {` 之后**插行**（纯追加，原有效果零回归） | **6 个国策** |
| `$ValuePatchMap` | **整块字面替换**（必须替换原行时用，如「宣称 → 核心」） | **5 个国策** |

🔄 **`$FocusPatchMap` 本轮改成【按挂载点分层】**：外层键 = 挂载点 id、内层键 = 国策 id。
原因：AST 那条线在 `australia_taog.txt`（挂载点 `ast_std`），SOV 那批在 `soviet.txt`（`sov_core`）
—— 原来的单层表 + `$FocusPatchHost`（写死一个文件）没法区分。`$FocusPatchHost` 已废弃。

> 州名与 owner 的判定方法：读 R56 `history/states/*.txt`，**按【州 id】归并（R56 覆盖原版）**，
> 再取 `owner == TAG` ∩ `add_core_of == TAG`。
> 🚩 **必须按 id 归并、不能按文件名归并** —— 两边文件名不同（原版 `1028 - Hamgyong.txt`
> vs R56 `1028-Dalarna.txt`），按文件名会把两个 mod 的州**混在一起**（本轮踩过，见 §6.3）。
