# 23 · 人物国策线写作手册（SOP）

> **用途**：为 7 人核心圈中**尚未做**的 6 人写个人国策线时，**按本文的顺序一步步来**。
> 顺序本身是本文的重点——它是我在托洛茨基身上**失败两次**之后才跑通的路子。
>
> 适用范围：任何"为史实人物设计国策线"的任务，不限于本 mod。

---

## 0. 为什么必须按顺序

我给托洛茨基设计过三版，前两版都被否，原因**都不是内容不对，而是顺序错了**：

| 版本 | 我做的事 | 为什么错 |
| --- | --- | --- |
| v1 | 凭史实印象列"可对应的国策卖点" | **不知道设计语言**——没读过德国核心圈与苏联政治线的实际写法，等于凭空造句 |
| v2 | 读了参照物，给出 7 个国策 | **并行清单**——7 个国策互不相关、无后续、无汇合，是 7 条死线而不是一棵树 |
| v3 | 按谱系与聚类设计 | ✅ 通过 |

**结论**：**先搞清楚素材之间的"关系"，再谈设计。** 没有关系结构的史实清单
（按理论/政治/军事/经济分类那种）看起来整齐，但**无法串成树**——
因为你不知道哪条推出哪条、哪条被推翻、哪条是另一条的铺垫。

## 1. 步骤清单（严格按序）

### ⏸ 例外：跨人物钩子 = **全局最后一步**（2026-09-15 用户定）

**第 5 步找的是「自己树内」的跨簇钩子**，照常做。

但 **跨人物钩子**（`prerequisite` 要求「某人已在核心圈」）**不归单个人物的流程管**：

| 原因 | 后果 |
| --- | --- |
| 它依赖**所有人的国策最终形态** | 现在某人还没设计完，你不知道他能提供哪些节点 |
| 一旦写进 `prerequisite`，对方的国家策被砍 / 改名 | **直接死锁**，而且不一定能静态查出来 |

→ **现在的跨人物钩子记录（`docs/21` §6.5、`docs/25` 第 5 步）都只是「草案」**，
**等全部人物定稿后统一做**（用户原话：「人物钩子这个放最后做……有个草案就行了」）。

### 第 0 步 · 查有没有现成内容（**先做这个，否则会重复劳动**）

- 在基座 mod（R56）与原版里搜这个人物的名字与相关 id
- **判定**：
  - 已有成体系的线 → **本 mod 只做"整合"，不重做**（例：斯米尔诺夫已有 `SOV_integrate_smirnovs_bloc`）
  - 有零星内容 → 记下来，设计时**绕开**
- 🚩 教训：**搜索范围要写下并复核**。我曾漏扫 `dlc\<name>\` 子目录，
  得出"布哈林没有大立绘"的错误结论，被用户当场纠正。

### 第 1 步 · 史实结构化（**不是分类，是建模**）

不要按领域分类。要回答四个问题：

| 问题 | 产出 | 托洛茨基的例子 |
| --- | --- | --- |
| 他的**根**是什么？（所有主张的立足点） | 1 条 | 不平衡与综合发展律 |
| 他的**主干**是什么？（最核心的那一条） | 1 条 | 不断革命论 |
| 主干**推出**了什么？（推论） | 1–3 条 | 一国社会主义不可能 / 第四国际 |
| 有哪些**并列要求**？（同一场斗争里的其它诉求） | 2–4 条 | 党内民主 / 经济计划化 / 中国革命问题 |

> 📌 **"根 → 主干 → 推论"这一串，就是将来 `prerequisite` 链条的蓝本。**
> 如果找不出推导关系，说明这个人的主张之间本来就没有强联系 ——
> 那就**不要硬做长链**，改成并列支线。

### 第 1b 步 · ⚠️ **非理论家怎么办：改用「历史重要贡献事件」建线**（2026-09-16 用户口径）

**触发条件**：这个人**没有成体系的理论著作**——查一手文库 0 篇目、或只有几篇应景文章。
**本项目 22 人里，这类人占大多数**（理论家只有托洛茨基 / 布哈林 / 季诺维也夫 /
普列奥布拉任斯基 / 拉狄克 5 个，其余 17 个都不是）。

**错误做法**：硬套「根理论 → 主干理论 → 推论」→ 找不到根，就开始**编排他的"理论"**，
结果做出一个不像他的人。

**正确做法**（用户原话：「可以看看他有没有什么**历史重要贡献事件**，
比如说托洛茨基的**缔造红军**就是很好的例子」）：

> **不要问他"主张什么"，要问他"实际做成了什么"。**

| 步骤 | 做法 |
| --- | --- |
| ① 拉职务年表 | 从传记里把他**历任职务的起止日期**全列出来（含兼职、特派员、委员会席位） |
| ② 找「做成了的事」 | 每个职务下问：**他在这个位子上把什么从无到有建立起来了？** 或**挡住了什么？** |
| ③ 一件事 = 一个节点 | 节点名 = 那件事，**不是**他的"思想" |
| ④ 按时间/因果排 | 职务年表本身就是天然的 `prerequisite` 拓扑序（先当这个职，才做那件事） |
| ⑤ 招牌职务 = 官衔链 | `Tiers` 用真实职务（照布哈林的三级官衔链做法） |

**样板对照**：

| | 理论家（托洛茨基） | **非理论家（李可夫）** |
| --- | --- | --- |
| 「根」 | 不平衡与综合发展律（**一条理论**） | 实用主义的温和派立场（**一条方法/态度**） |
| 节点长什么样 | 「不断革命论」「不平衡与综合发展律」 | **「劳动国防委员会粮秣特派员」「红军给养体系」** |
| 什么算好节点 | 一个能推出其它主张的**理论命题** | **一件真实发生过、有年月、有职务依托的事** |
| 样板节点 | **缔造红军** —— 注意：这**不是理论**，是**他实际建成的一支军队** | **接过列宁的人民委员会主席**、**酒类专卖（Rykovka）** |

> 💡 **「缔造红军」为什么是好样板**：它有**主体**（他）、**动作**（缔造）、
> **从无到有的产物**（一支军队）、**可考的年份**（1918–1921）。
> 反例（坏节点）：「重视军事建设」——没有主体动作，是评价不是事件。

> 🚩 **对非理论家，描述文本的来源也要跟着换**：
> 理论家能引他自己的著作；非理论家往往只能引
> **②历史他人的记述**或**③法令/报告/命令原文**（`docs/23` §7.1 的优先级 2–3 档）。
> 查一手文库时**先探有没有他的篇目页**（`/chinese/<姓氏>/index.htm`），**别默认人人都有**。

### 第 2 步 · 有效性判定（**哪条不能算贡献**）

三档，逐条标：

| 档 | 定义 | 托洛茨基的例子 |
| --- | --- | --- |
| ✅ 算贡献 | 当时被否/被压制，但后续被证明或成为源头 | 不断革命论、中国革命问题 |
| ⚠️ 战术主张 | 一次性判断，对错都不构成理论贡献 | 布列斯特「不战不和」 |
| ❌ **不能算贡献** | 被否决**且他自己后来放弃或接受了对方看法** | 劳动军、工会国家化 |

> 📌 **❌ 那一档极其重要，也最容易写错。** 因为被否决的主张往往**最有"国策味"**，
> 但写进去**与人物本人的立场相反**。
> **处理方式不是删掉，而是把它做成「互斥且收益更差」的选项**（见第 5 步）。

### 第 3 步 · 奠基性判定（**哪条成了什么的源头**）

逐条问：**这条后来变成了什么？**

- 1923 十二大经济提纲 → 多伊彻称「苏联经济史上最关键的文件」→ 1928 五年计划
- 反法西斯统一战线 → 1935 共产国际七大人民阵线

> 📌 **奠基性最强的条目，应当放在所在支线的末端**，作为该线的收尾。
> 因为它"通向未来"，放在末端最有分量。

### 第 4 步 · 聚类 → **支线**

把第 1–3 步的条目按**"互为依据 / 同一斗争的不同侧面"**聚成簇。

- **簇数 = 支线数**
- **簇内顺序 = 簇内的因果顺序**（先发生/先决的在前）

托洛茨基的六簇见 `docs/21` §5；其中五簇成了五条支线。

### 第 5 步 · 找跨簇钩子（**这一步决定树是"网状"还是"平行"**）

逐簇对问：**这两簇之间有没有真实的因果/隶属关系？**

- 有 → 用 **`prerequisite` 的两个块（= AND）** 表达（例：中国革命问题同时需要国际线节点与党内民主线节点）
- 无 → 就让它平行，**不要硬连**

> 📌 托洛茨基全树**只留了一条**跨簇钩子。钩子太多会让树不可读。

### 第 6 步 · 设计（形状照德国四层）

```text
层 1 枢纽 → 层 2 入口(每人 1 个) → 层 3 支线(每条 2–4 个) → 层 4 汇合(2 个互斥)
```

**三条硬规则**（都是用户明确纠正过我的）：

| 规则 | 原因 |
| --- | --- |
| **全部 `cost = 2`** | 核心圈是小国策。政治线的 5/10 是**另一种类型**，只借主题不借花销 |
| **不挂派系门槛** | `available` 只认「是否已入席」。挂派系会让走别的路线的人一点红利吃不到 |
| **不碰国家领袖线** | 领袖线自成系统，核心圈不接，也不拿它当奖励 |

**汇合层照德国**：多个 `prerequisite` 并列（= OR）+ `count_triggers = { amount = N }` 门控
（N ≈ 支线数 × 0.6，德国是 5 条走通 3 条）+ **两个互斥结局**。

**❌ 档条目的处理（第 2 步的落地）**：

```text
被否的选项 A ─┐
              ├─ 互斥 ─→ 真正的贡献（前置写「A 或 B」，同一块内 = OR）
被否的选项 B ─┘
```
- 两个被否选项**互斥**
- ❌ 那个**不给政治点、idea 带负面修正**，明显吃亏
- 但**两条路都通向真正的贡献**——因为历史上他确实两条都试过

### 第 7 步 · 落实

| 事项 | 做法 |
| --- | --- |
| **点名真实角色** | 扫角色文件确认存在且**有可用身份**（`corps_commander` / `advisor` / `field_marshal`）。⚠️ 同名不同人要小心（列夫·加米涅夫 ≠ 谢尔盖·加米涅夫） |
| **idea 数值** | 照德国模板：`allowed = { always = no }` + `removal_cost = -1` + `modifier`，且**统一带 `political_power_gain = -0.1` 作为"入圈代价"** |
| **修正词条** | **只从已实测词汇表里挑**（见 `docs/22` §8.0），不臆造 |
| **本地化文本** | **必须是节选，不能自撰**（见下方 7.1） |
| **本地化格式** | `<focus_id>` + `<focus_id>_desc`；UTF-8 **带 BOM**、首行 `l_simp_chinese:`、文件名含 `_l_simp_chinese` |
| **文件** | 新建自定义文件名，**绝不塞进原版文件名** |

#### 7.1 描述文本必须是史实/理论节选（**硬规则**）

**不要自己写评价。** 自撰的描述会掺进模型的判断，与史实不符。按下面优先级取文本：

| 优先级 | 取什么 | 例 |
| --- | --- | --- |
| 1 | **本人的原文**（著作 / 军令 / 报告 / 发言） | 托洛茨基对通讯封锁的复信：「只有腐朽透顶的官僚集团才会要求做出这种放弃」 |
| 2 | **理论原文**（他的或别人的，如辞典条目） | 《马克思主义思想辞典》「托洛茨基主义」条目本句 |
| 3 | **历史上他人的记述或评价原文**（同时代人 / 权威传记 / 权威条目） | 多伊彻、怀特、年谱；高尔基转述的列宁语 |
| 4 | 译自外文权威条目（英文 Britannica 等）—— **在待办里记下「待换中文原文」** | — |

**写法**：

```yaml
 <focus_id>_desc:0 "一段话。不要引号，不要写「—— 出处」，贴合国策题目最重要。"
```

- **一段话即可**。不要 `\n` 分段，不要把引文和出处拼在一起塞进游戏文本。
- **出处不要进游戏文本**，但**必须记在配套的设计文档里**（如 `docs/22` §8.3 的引文来源注），
  以便日后核对与替换。

> 🚩 **贴题优先于文采。** 一段引文若与国策题目不对应（例如用「论战的分量」去讲「驳一国社会主义」），
> 就该换一段 —— 哪怕原来那段更漂亮。
> 优先找「辞典/百科条目」而不是通读传记，条目里常有可直接用的判定句。

### 第 8 步 · 校验

1. 写进 `build/gen-hof-ic-s3.ps1` 的**单一数据源**（不要手写进 `soviet.txt`）
2. `sync-from-r56.ps1` → **锚点唯一性必须通过**
3. `verify-s2.ps1` → **失败项必须为 0**
4. 必要时进游戏看 `error.log` 无本次新增错误

## 2. 扩展深度怎么定（"写多少个国策"）

不要凭感觉。按下面四步推：

| 因素 | 影响 |
| --- | --- |
| **簇数** | 决定支线数。3 簇 → 3 条支线，不要硬凑到 5 |
| **每簇内的独立事件数** | 决定该支线深度。2 个事件就 2 个国策，**不要注水到 4 个** |
| **是否与他人主题重叠** | 重叠的簇要**缩减或让给 R56**（党内民主线只留 2 个，因为 R56 已占） |
| **奠基性条目的数量** | 每条筑基条目天然是该支线的**末端节点** |

**总国策数** ≈ `1（入口） + Σ支线节点 + 2（汇合）`。

托洛茨基的结果：`1 + 15 + 2 = 18`。

> ⚠️ **克制的原则**：宁可少也不要注水。
> 托洛茨基素材量是希姆莱（6 个国策）的三倍，但我也只给到 15 个支线节点 ——
> 因为**簇只有五簇**。**支线数是簇数决定的，不是热情决定的。**

## 2.5 德国核心圈的编写思路（2026-09-15 补 · 决定「几条支线」）

来源：`germany.txt` 全部 30 个含 `FOCUS_FILTER_INNER_CIRCLE` 的国策
（扫描件 `docs/reference/reports/ic-all-report.txt`）。完整字段清单见 `docs/20` §0.5 A / A2。

### 结构

| 层 | 数量 | cost | 讲什么 |
| --- | --- | --- | --- |
| 枢纽 | 1 | 5 | 核心圈总开关 |
| **入口** | **每角色 1 个** | **2** | **他是谁**（给招牌 idea） |
| **子线** | **每角色 1–4 个** | `@inner_circle_time_tier_N` | **他到底做成了什么** |
| 汇合 | 2（互斥） | 5 | 收束方向 |

### 🚩 三条必须记住的编写原则

**① 子线讲「他做成了什么」，不是「他反对什么」。**

德国 23 条子线**全部是正面成就**：

```text
托特   GER_form_organization_todt → GER_autonomous_organization_todt
希姆莱 GER_expand_gestapo → GER_absorb_the_abwehr → GER_hegemony_of_the_ss
```

**一条「反对 XX」都没有。** 反对性主张要么归入正面命题，要么做成互斥选项。

**② 同一条主张的「正说 / 反说」只算一个节点。**

「平衡增长」的正面表述是「按比例的劳动消耗规律」；
「反剪刀差」「反超高速工业化」是**同一命题的否定式**，不是三个独立贡献。
**写在一条子线里当不同节点可以，拆成三条支线就是注水。**

**③ 支线数 = 簇数，不硬凑。**

本文 §2 原话：**「3 簇 → 3 条支线，不要硬凑到 5」**。德国的上限是**每角色 4 条**。

### 🚩🚩 「反对 XX」的准入判据 —— **三问**（2026-09-15 用户定）

用户原话：

> **「托洛茨基的反对官僚化有它的理论和历史意义，推进和证实了官僚主义在社会主义国家的弊端，
> 并对现世的社会主义国家治理也有启示作用（现在苏联的官僚主义仍然是批评苏联的重要内容）。
> 除非和托洛茨基这个一样，不然『反对 XX』就不加进去。」**

一条**否定式主张**（「反对 XX」）只有在**三问全过**时才算独立贡献：

| # | 问什么 | ✅ 正面样板：托洛茨基「反对官僚化」 | ❌ 反例：布哈林「反超高速工业化」 |
| :-: | --- | --- | --- |
| **1** | 它能**转写成一句正面的理论命题**吗？（且不是别条目的否定式） | ✅ 正面形式 = **「党会代替无产阶级」的警告** —— 工人国家自身的官僚化 | ✗ 只能写成「工业不能取之过度」= **「平衡增长」的否定式** |
| **2** | 它**提出了此前没人系统提出的问题**吗？ | ✅ 社会主义国家**自身**的官僚化，此前无人系统论述 | ✗ 工业化速度之争，列宁、托洛茨基都谈过 |
| **3** | 它有**独立的后续影响**吗？（后出著作 / 被历史证实 / **对后世治理有启示**） | ✅ 《被背叛的革命》(1936) 系统化；**至今仍是批评苏联体制的核心内容** | ✗ 后续被继承的是「平衡增长」，「反超高速」本身没留下概念 |

**判定规则**

- **三问全过** → 可作为**独立条目**（甚至独立支线）
- **任一不过** → **不单列**。要么归入它所否定的那条正面主张（当节点），
  要么做成**互斥且明显更差**的选项（承接第 2 步）

> 💡 **第 3 问里的「对后世治理有启示」是用户特别强调的维度** ——
> 一个「反对」如果只活在当事人自己的年代，就只是**历史事件**（可做叙事节点），
> 不是**理论贡献**（才配独立成条）。

### 合并判据（一句话）

> **「如果这两簇合并，会不会丢掉一个独立的理论主张？」**
> - 不会 → **合并**（它们本来就是同一条）

### 🚩🚩 主干健不健壮：两条新增判据（2026-09-17 施利亚普尼科夫第二版加的）

> ⭐⭐ **判据 A（去重要去到隐喻层）**

>   ⚠️ **但只比【能同席的那些人】** —— 与本人互斥的人**不必比**（见下面判据 E）。

### 🚩🚩 该照抄的是「**区块避让法**」，不是那个具体形状

> **用户 2026-09-15 纠正**：
> 「从托洛茨基的入口列**往两侧铺开**，要是侵占别人的列**别人避让**不就行了，又不能不灵活调整。
> 也就是**每个人算一下区块大小然后各自避让**不就好了。」
>
> ❌ **我上一版把它读成了硬规则**（"一人一列区、不能侵占邻居"）—— **错了**。
> 德国那 15×6 的形状是**各人区块互相避让之后的结果**，不是约束。

**方法（四步）**：

| 步 | 做什么 |
| :-: | --- |
| **1** | **算每人的区块宽度** = 支线数 × 每支线占列数（分叉时 +1） |
| **2** | **从入口向两侧铺开** —— 支线在入口左右展开，不必挤在入口正下方 |
| **3** | **依次摆放 + 避让** —— 撞上别人的区块就**整体让开**（往右挪），区块之间留 1 格 |
| **4** | 纵向一律 dy = 1（同一条支线内逐层向下） |

**德国的避让痕迹**（入口 x 为 54, 56, 58, 61, 64, 66）：

- 托特占 54..56 → 施佩尔的入口就紧贴在 **56**
- 希姆莱的支线要左右各 1 格（60 与 62）→ 入口居中放在 **61**
- 戈培尔只 1 条链 → 入口 **64**（单列）
- 赫斯两条支线在 66/68 → 入口靠左放在 **66**

> 💡 **入口间距不等距**就是避让的结果 —— 不是刻意排的。

### 2.7 🚩 我们的偏差（**待修**）

| 项 | 德国 | 我们（`docs/22` 托洛茨基现状） |
| --- | --- | --- |
| 入口间距 | **不等距**（2,2,3,3,2）—— 按每人区块宽度定 | **写死等距 2**（`$seatX = @(-6,-4,-2,0,2,4,6)`） |
| 支线展开 | **从入口向两侧铺开**，区块互相避让 | 托洛茨基横铺 11 格（49..67），**没算别人** |

**后果**：托洛茨基的区块（49..67）盖住了布哈林的入口位置（61）。

**修正（按德国的方法，不是拉大间距）**：

1. 先算 7 人**各自的区块宽度**（支线数 × 每支线列数）
2. 从锚点下方开始，**依次摆放 + 避让**（相邻区块留 1 格）
3. 入口 x 取该区块的**合适位置**（居中或靠边）
4. 入口间距自然变成**不等距**

> 📌 **实现上**：生成器里的 `$seatX` 数组改成**按区块宽度算出来的**，而不是写死 `@(-6,-4,-2,0,2,4,6)`；
> 每人的国策坐标继续用 `relative_position_id = 自己的入口`（这样入口挪了，树跟着挪，不用改子坐标）。
>
> ⚠️ **后 5 人还没设计，区块宽度未知** —— 现阶段只先把**托洛茨基与布哈林**两个区块摆开，
> 以后人齐了再整排（反正相对坐标不会因入口挪动而失效）。
