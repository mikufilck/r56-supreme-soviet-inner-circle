##### 2.4.2.6 实施方式（照 §2.4.1，**不用** `mutually_exclusive`）

写进**席位入口国策的 `available`**，而不是国策互斥 —— 这样**可逆**：
对头被替换出局后，这条路自动重新打开。

```text
focus = {
    id = hof_ic_seat_<key>
    available = {
        hof_ic_is_appointment_cd_over = yes
        NOT = { hof_ic_seated_<key> = yes }
        NOT = { hof_ic_seated_<对头 1 的 key> = yes }   # ← R1/R2/R3 展开
        NOT = { hof_ic_seated_<对头 2 的 key> = yes }
        ...
    }
}
```

- **展开由生成器完成**：`build/gen-hof-ic-s3.ps1` 里的 `$camps`（营表）/
  `$crossRules`（营×营 全交叉）/ `$pairRules`（逐对）/ `$exclOf`（展平后的结果）
- 只对**同时在册**的两人之间生成条件 → **池子扩员时自动生效**，不用改逻辑
- **当前实测量（2026-09-20 实测）**：**22 人全部在册** → 条件 = 22（各席位自身）+ **74 对** × 2 = **170 条**
  （生成器自检项「席位互斥条件」实测 实际=170 期望=170）
  📌 历史：在册 7 人时 = 25 条；21 人时 = 73 对 / 168 条；**加入马林科夫后 = 74 对 / 170 条**
- ⚠️ **不要写成 `mutually_exclusive`** —— 那是永久锁死，玩家点错一次无法挽回（§2.4.1）

```text
    completion_reward_joint_member        只给【加入方】
```

外加 `offset = { x = .. y = .. trigger = { tag = .. } }` 可按国家错开摆位。

**结论三："同一阵营 + 至少一方是领袖 + 双方共产"的官方惯用写法。**

官方把这类条件封成 scripted_trigger，范本是
`common\scripted_triggers\NORDIC_scripted_triggers.txt` L198 的 `NORDIC_basic_joint_trigger`：

```text
NORDIC_basic_joint_trigger = {
    custom_trigger_tooltip = {
        tooltip = NORDIC_is_joint_focus_member_TT
        is_in_faction = yes
        OR = {
            has_country_flag = NORDIC_council_leader
            ...
            AND = {
                has_variable = global.NORDIC_alliance_leader
                is_in_faction_with = var:global.NORDIC_alliance_leader
            }
        }
    }
}
```

已确认可用的触发器（均在原版实测到）：

| 触发器 | 用途 |
| --- | --- |
| `is_in_faction = yes` | 自己必须在某阵营内 |
| `is_in_faction_with = <TAG>` | 与指定国家同阵营（官方用了 16 次） |
| `is_faction_leader = yes` | 自己是阵营领袖（官方大量使用） |
| `has_government = communism` | 共产主义政体 |
| `any_allied_country = { ... }` | "我的任一盟国满足…" |
| `custom_trigger_tooltip = { tooltip = X  <条件> }` | 给条件挂自定义提示文案 |

> 还有一个范例是 `HABSBURG_joint_trigger`（`HUN_scripted_triggers.txt` L213），
> 用 `OR = { tag = global.AH_originator_country  is_in_faction_with = global.AH_originator_country }`
> 让**发起方与加入方共用同一个触发器**——这正是我们两国场景需要的对称写法。

**结论四：尚有 2 处仍需实测**（写代码时按此评估风险）：

- `cancel_if_invalid` / `continue_if_invalid` 的确切语义（范例里是 `yes` / `no`）；
- 脱离阵营后已点国策是否失效（对应上面的待确认 2）。

## 5. 成本评估（**这是本方案最大的风险点**）

### 5.1 为什么成本这么高

`shared_focus = <名字>` 这个引用**必须写在每一棵要使用它的国策树内部**。而 HOI4 是**整文件覆盖**——所以：

> **每让一个国家参与联合国策，就要把该国整棵国策树文件复制进本 mod。**

没有"只加一行"的办法，也没有"跨 mod 追加"的机制。

### 5.2 实际数字

⚠️ **本节已于 R6 修订**。原估算偏低，原因是漏算了「同一国家可选用原版 DLC 树 / R56 树」造成的额外挂载点。完整矩阵见 **`14-tree-attachment-matrix.md`**。

> ⭐ **2026-09-21 实测**：挂载点已扩到 **22 个**（加暹罗），`sync-from-r56.ps1` 实测 **成功 22 / 失败 0 / 236,948 行**；
> （2026-09-20 是 21 个 / 227,304 行）此前实测
> **成功 21 / 失败 0 / 合计 227,304 行**（新增四国 +21,606 行）。

| 需求 | 需复制的文件 | 只支持默认树 | 全部支持（含可选树） |
| --- | --- | --- | --- |
| A 核心圈 | `soviet.txt` | 29,564 | 29,564 |
| B 中苏联合 | SOV 共用 + PRC | +14,652 | +22,243 |
| C 互助会（**15 国**） | 蒙古、芬兰、瑞典、挪威、丹麦、冰岛、阿富汗、沙特、菲律宾、古巴、阿根廷、埃塞俄比亚、法国、波兰、匈牙利 | +≈153,100 | +≈223,900 |
| **合计** | | **17 个文件 / ≈197,300 行** | **29 个文件 / ≈275,700 行** |

**两处关键修正**

1. **PRC 挂的不是 `china_communist.txt`。** 因为本机装有 `No Compromise, No Surrender`，`china_communist_sea.txt` 的 `china_communist_focus_sea` 在 MTTH 里得 1000 分，碾压 `china_communist.txt` 的 10 分。**需求 B 必须改 `china_communist_sea.txt`**（14,652 行，近两倍）。
2. **15 国里有 11 国的树不唯一**，且**默认值按国家各不相同**（瑞典/挪威/阿富汗默认 R56 树；丹麦/冰岛默认原版树）。只改一棵树会让一半玩家看不到互助会分支。

（匈牙利挂载对象已于 Q22 确定为 `wuw_hungarian_focus`，按 20,119 行计。）

### 5.3 由此带来的维护负担

1. **覆盖链变三层**：原版 → R56 → 本 mod。我们复制的那 17 个文件全部被"冻结"。
2. **R56 每次更新**这些文件，我们都必须重新合并，否则玩家的 R56 更新会被我们的旧副本顶掉——**这是最容易引发玩家投诉的事故类型**。
3. 需要一个**同步脚本**：从 R56 的对应文件自动生成本 mod 副本，并在 `# hof:begin/end` 锚点注入我们的补丁。这是把这个项目做得可维护的**前提条件**。
4. 我们的 `.mod` 必须排在 R56 之后加载：`dependencies = { "The road to 56 CN" }`（name 已从实际文件读到，不是猜的）。

### 5.4 ❌ 折中方案（已被否决，仅存档）

原提案：互助会做成"苏联单方面的国策"，只在 `soviet.txt` 里做，通过效果给其他参与国施加 dynamic modifier / 国家精神 / 阵营关系，**不在对方的树里加任何国策**。成本可从 16.9 万行降到 2.96 万行单文件。

**用户决定：否决。** 理由是接受多国挂载的成本——有 AI 辅助批量修改，且参与国必须能在自己的国策树里点到专属分支，这是玩法需求而非纯成本问题。

保留此节只为记录决策过程，**不作为实施方案**。

## 6.5 命名规范（按可维护性设计）

设计原则：**前缀 → 类别 → 归属 → 序号**。任何对象都能靠 `hof_` 前缀全局检索；所有变量与 GUI 组件加前缀，避免与 R56 自带的 17 个 scripted gui 撞名。

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 角色键 | 姓氏小写 ASCII | `trotsky`、`bukharin`、`tukhachevsky` |
| 国策 id（核心圈） | `hof_ic_<角色键>_<nn>` | `hof_ic_trotsky_01` |
| 国策 id（联合国策） | `hof_jf_<线路>_<nn>` | `hof_jf_mutual_aid_eco_01` |
| 联合国策定义名 | `hof_jf_<线路>` | `hof_jf_sino_soviet`、`hof_jf_mutual_aid` |
| 图标 | `GFX_hof_ic_<角色键>` / `GFX_hof_jf_<线路>_<nn>` | `GFX_hof_ic_trotsky` |
| 席位框架图 | `GFX_hof_ic_slot_frame_<1..5>` | — |
| GUI 组件 | `hof_ic_ui_window` | — |
| 席位变量 | `hof_ic_slot_<1..5>` | 存该席位所属角色的序号 |
| 成员标记 | `hof_ic_member_<角色键>` | `hof_ic_member_trotsky` |
| 动态民族精神 | `hof_ic_spirit_<角色键>` | `hof_ic_spirit_trotsky` |
| 本地化键 | `hof_ic_<角色键>_name` / `_desc`、`hof_jf_<线路>_<nn>_name` / `_desc` | — |
| 文件 | `hof_ic_*.txt`、`hof_jf_*.txt`、`hof_icons.gfx`、`hof_*_l_simp_chinese.yml` | — |

**两条硬约束**（来自 `04-localisation.md`，写错会静默失败）：

- 本地化文件名**必须含** `_l_simp_chinese`，首行**必须**是 `l_simp_chinese:`
- `.yml` 存为 **UTF-8 with BOM**；脚本 `.txt` 与 `descriptor.mod` 存为 **UTF-8 不带 BOM**
