### 抓取时踩的 3 个坑（都已修，写在这里省得下次再踩）

1. 🚩🚩 **一人一个请求会被限流**：连发 10 个请求后维基开始返 **HTTP 429**，第 6 人起全挂。
   → 改成批量 `titles=A|B|C`。
2. 🚩🚩 **批量取整篇全文时 `exlimit` 被强制降为 1**，API 会明确警告
   `"exlimit" was too large for a whole article extracts request, lowered to 1.`
   → 表现是「15 条里只有 1 条有 `extract`，其余只有标题、内容 0 字节」。
   → **加 `exintro=1` 才允许 `exlimit=max`（20）**。想要全文只能一条一条抓。
3. 🚩🚩 **两处 PowerShell 插值坑**（同一个病因）：
   - `"https://$Lang.wikipedia.org/..."` → `$Lang.wikipedia` 被当成**属性访问** → URL 变 `https://.org/...`。
     一律写 `$($Lang)`。
   - `& curl.exe @a` 的输出会被 PowerShell **按行拆成数组**，喂给 `ConvertFrom-Json` 抛异常
     （表现为「前几个人成功、后面全 FAIL」）。→ 让 curl 用 `-o` 直接写文件。

**⚠️ 这 15 人的「个人国策线」仍完全没做** —— 那是 `docs/23` SOP 的第 2~8 步，
每人一份 `docs/2x-<人>-genealogy.md`。**与本批图标是两条独立的工作流**
（图标只需要肖像 + 职务，两样现在都齐了）。

## 4. 接入时改了什么（2026-09-16 已执行完，留档备查）

`$roster` 从 7 扩到 22，**实际动了这几处**：

| 位置 | 原状 | 现状 |
| --- | --- | --- |
| `$roster.Count -ne $seatCount` 断言 | 要求花名册 == 7（直接 throw） | 已改为 `-lt` throw + `-ne` 时只打容差提示 |
| `$seatCount` | 7 | **没动**（席位仍是 7 个） |
| `$camps` 的六个营 | 只对「同时在 `$roster` 里」的两人生成互斥 | 自动生效，**没改代码**，但互斥对从 9 涨到 73 |
| `$slots` / `hof_ic_slot_N` | `N = 1..7` 存 `$roster[].Idx` | **没动**（存候选人的 Idx，仍 7 个槽位） |
| `SeatDesc` | 每人一条（有守卫，缺就 throw） | 新人 15 条已各写一条（德式三段式） |
| `art` 立绘 → sprite | 7 人已注册 | 新人 **11 人有 `NewArt`**（自绘）、**11 人用原版/R56 大图**（含图哈切夫斯基等 4 人，`docs/17` §5 明定不用画）。22 人**人人有立绘**，§0 校验 22/22 全过 |
| **§11 四条写死的断言**（`sync_rank` / `appoint` / `seated` 各 7，`spriteType` 14） | 写死 7 / 14 | 🚩 **改 22 人时全部报 FAIL**，已一律改成从数据算（`$roster.Count`） |
| **§11③ 中立营「互斥数 = 0」** | 写死 0 | 🚩 **扩到 22 人即崩**（图哈切夫斯基↔伏罗希洛夫）。已改为只统计 R2/R3 |
| `verify-s2.ps1` 11c「hub 补丁标记 == 1 对」 | 要求旧补丁标记恰好 1 对 | 已改为**要求 0 对** + 检查自建 `hof_ic_commissar` |
| `verify-s2.ps1` 11e「席位首级 idea == 7」 | 写死 7 | 已改为 == `$roster` 人数（从 `_sync_rank` 效果数推导） |

> 🚩 **`$roster[].Idx` 必须全局唯一且不复用** —— 它写进 `hof_ic_slot_N` 存档，
> 改号会让老存档的席位对错人。

> 🚩🚩 **教训：任何「按人一份」的计数都别写死。** 本轮共撞到 **6 处**写死 7/14 的断言，
